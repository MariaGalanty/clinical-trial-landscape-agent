# Clinical Trial Landscape Agent

An evidence-grounded agent that answers questions about clinical trials for a
given disease, starting with **why trials were stopped**.

It fetches studies from ClinicalTrials.gov and classifies the stated stop
reason with an LLM. When the registry text is too vague, it searches PubMed
for evidence. Every answer carries its sources. If no evidence is found, the
answer is an explicit `not_found`, never a guess.

> **Status: work in progress.** The registry pipeline, the LLM classifier and
> the PubMed tools work. The PubMed agent that handles vague cases is being
> built now.

## Why

Registry stop reasons are often short and vague: "Sponsor decision",
"Business reasons", or empty. A landscape review needs to know *why* a drug
programme stopped, and it needs to be able to check that answer. So the
project is built around three rules:

- **Grounded:** the model classifies only the text it is given, not what it
  remembers about a drug or sponsor.
- **Cited:** every answer lists its sources (the registry record or PubMed
  IDs). A citation check rejects any PMID that was not actually fetched during
  the run.
- **Honest about gaps:** `not_found` is a valid result. A wrong `found` is
  worse than a correct `not_found`.

## How it works

```text
ClinicalTrials.gov API
    -> flatten + filter drug trials             (registry.py)
    -> route_trial(trial, question)             (router.py)
    -> handler chain, stops at the first "found":
         1. LLM classifier on the registry text (why_stopped_handler.py)
         2. PubMed agent for vague cases        (in progress)
    -> Evidence: answer, category, sources, status
```

Each handler returns the same Pydantic `Evidence` model
([src/evidence.py](src/evidence.py)). That means handlers can be added,
reordered or swapped without changing the rest of the pipeline. The LLM
provider is kept behind the handler, so OpenAI can later be replaced with a
local model (e.g. Ollama).

### Stop-reason categories

| Category | Meaning |
|---|---|
| `efficacy_futility` | The treatment did not work, or was unlikely to |
| `safety` | Adverse events, toxicity or other safety concerns |
| `business_strategic` | Funding, sponsor strategy, regulatory or commercial reasons |
| `enrolment` | Difficulty recruiting or retaining participants |
| `other` | A specific reason outside these (e.g. drug supply, pandemic) |
| `unclear` | No real reason given; the chain passes it to the next handler |

The classifier uses structured output, so the model must return one of these
labels.

## Evaluation

Every stopped ALS trial with a stop reason was labelled by hand, and prompt
versions are compared against those labels. Repeated runs of the *same* prompt
were also compared, to measure how much labels change from run to run, because
a prompt change smaller than that noise means nothing. The write-up of the
errors is in
[eval/error_analysis_why_stopped.md](eval/error_analysis_why_stopped.md).

A held-out evaluation set is planned. Until then, no accuracy figures are
reported, because the current labels were also used to tune the prompt.

## Project structure

```text
src/
├── registry.py             ClinicalTrials.gov fetch, pagination, flattening
├── drug.py                 drug-name normalization and grouping
├── evidence.py             Pydantic models: Source, Evidence, WhyStoppedLabel
├── router.py               handler chains per question
├── status_handler.py       trial status from the registry
├── why_stopped_handler.py  LLM stop-reason classifier and prompt
├── run_why_stopped.py      resumable batch run over all stopped trials
├── pubmed.py               PubMed E-utilities: search, fetch, XML parsing
├── explore_pubmed.py       PubMed search hits vs registry references
└── test_*.py               plain Python checks (no API calls in test_router)
eval/                       hand labels and error analysis
data/                       raw, interim and processed data (not in git)
```

## Setup

Requires Python 3.12+ and [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env
```

Add these to `.env`:

```text
OPENAI_API_KEY=...
NCBI_EMAIL=you@example.com   # NCBI asks every E-utilities client to send one
```

## Usage

```bash
# 1. Fetch and save all ALS drug trials
uv run python src/registry.py

# 2. Classify stop reasons (resumable; safe to re-run)
uv run python src/run_why_stopped.py

# 3. Checks
uv run python src/test_router.py
uv run python src/test_pubmed.py
```
